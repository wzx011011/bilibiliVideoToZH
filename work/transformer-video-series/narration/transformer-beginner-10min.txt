如果你只记住一句话：Transformer 是一种让一句话里的每个词，都能参考其他词，再决定自己该怎么理解的结构。今天我们不用先背公式，也不假设你学过机器学习。十分钟后，你会知道它为什么能读懂上下文，为什么 GPT 能一个字一个字地写回答，以及“注意力”到底在注意什么。

先看一个看似简单的问题。人读到“我把书放到桌子上，因为它很重”时，知道“它”大概率指书；读到“我把书放到桌子上，因为它很旧”时，也知道“它”可能还是书。我们几乎没有意识到自己做了判断，但计算机看到的最开始只是一串符号。它不知道书是什么，桌子是什么，更不知道“它”该指谁。语言模型要做的事，就是把这种符号关系变成可以计算的表示。

第一步叫 Token。模型并不是直接把整句话当作中文来读，它会先切成一小块一小块的 Token。一个 Token 有时是一个汉字，有时是一个词的一部分，也可能是标点。你可以把它理解成模型手里的积木编号。“Transformer 很有用”被切开后，模型得到的不是意思，而是一排编号。编号本身没有温度，也没有语义，它只是告诉模型：这里出现了第几号积木。

第二步是把编号变成向量。向量听起来像数学词，其实可以把它想成一串很多维的坐标。每个 Token 都会查一张很大的表，取出属于自己的坐标。意思相近的词，常常会在这个坐标空间里更接近；比如“猫”和“狗”可能比“猫”和“发动机”更像。注意，这一步仍然没有真正理解句子。它只是把不能计算的文字，翻译成神经网络能处理的数字。

早期模型常用循环神经网络，也就是 RNN。它像一个人沿着句子排队走：先看第一个词，把记忆交给第二个词，再交给第三个词。它的好处是顺序天然存在，但代价也明显。后面的词要知道前面的信息，必须沿着很长的链条传递。句子越长，早期信息越容易被冲淡；而且每一步都依赖前一步，训练时很难充分并行。这就是 Transformer 想解决的第一个问题。

Transformer 的关键转变是：不要让信息只沿着一条队伍慢慢传。让每个位置一开始就有机会查看整句话。回到“我把书放到桌子上，因为它很重”。当模型处理“它”时，它不必等前面的词把消息一级一级传过来。它可以直接看“书”“桌子”“很重”等位置，然后根据当前任务决定哪些位置值得多看一点。这个“多看一点、少看一点”的过程，就是 Attention，也就是注意力。

这里有一个很重要的直觉。注意力不是在找唯一正确答案，更像调节音量。模型会给句子里的其他 Token 分配不同的权重。处理“它”时，“书”的音量可能很大，“桌子”的音量小一些，“因为”和“上”更小。接着，模型把这些被调过音量的信息合在一起，得到“它”在当前上下文里的新表示。所以同一个字，在不同句子里可以有不同含义；它不是靠字典里写死的解释，而是靠周围内容实时决定。

为了把这个过程说清楚，论文给每个 Token 准备了三种角色：Query、Key 和 Value。先别被英文吓到。你可以把 Query 想成“我现在想找什么”；Key 是“我这里有什么线索”；Value 是“如果你关注我，我真正能提供什么内容”。当“它”这个位置发出 Query，它会拿着自己的问题，去和每个 Token 的 Key 比较。比较得分高，代表对方的线索和当前问题更匹配。最后，它从高分位置拿走更多 Value，组合成新的自己。

如果一定要看一眼计算，核心只有三步。第一，Query 和每个 Key 做匹配，得到一排分数。第二，把分数变成总和为一的比例，这一步叫 Softmax。第三，用这些比例去加权求和所有 Value。比如分数最后变成百分之六十、百分之二十五、百分之十和百分之五，模型就会让最重要的位置贡献最多信息。你不需要手算矩阵；只要记住，注意力把“我该参考谁”变成了一组可以学习的比例。

一个注意力头只能用一种角度观察关系，所以 Transformer 通常会同时使用多个头。可以把它理解成几位读者同时读一句话：一个更关注主谓关系，一个更关注代词指代，一个更关注否定词，还有一个可能注意时间和地点。它们各自给出结果，再拼到一起。多头注意力不是让模型变得神秘，而是让它能并行保留多种关系。语言里的含义往往不只一种线索，多几个视角会更稳。

到这里还有一个漏洞：Attention 天生不知道顺序。如果只给它“我”“喜欢”“你”这三个 Token，它看到的是三个向量的集合；“我喜欢你”和“你喜欢我”用了相同的词，却显然不是同一个意思。解决办法是位置编码。模型会给每个 Token 再加上一份表示位置的数字，好比给积木贴上座位号。现在输入不只是“这是什么词”，还包括“它出现在第几个位置”。这样，注意力在看全句时不会丢掉先后关系。

把这些零件放进一层 Transformer 里，可以把它拆成两个主要步骤。先是注意力层：Token 之间交换信息，让每个位置看看别人。后是前馈网络，也叫 Feed Forward Network：每个位置单独处理刚收到的信息，像每个人回到自己的桌前消化笔记。每个步骤外面还有残差连接和归一化。残差连接允许原来的信息走一条快捷通道，归一化让数值不要忽大忽小。它们听起来不抢眼，却是把几十层、上百层网络稳定堆起来的工程基础。

最早的 Transformer 同时有编码器和解码器。编码器负责把输入整句读懂，解码器负责根据理解结果生成输出。翻译任务里，编码器读英文，解码器写中文。今天常见的大语言模型，例如 GPT，通常使用的是 Decoder-only 结构。它不需要先完整读一遍再翻译，而是持续根据已经出现的 Token 预测下一个 Token。虽然结构选择不同，里面的注意力、前馈网络、残差和归一化这些核心积木仍然一样。

这也解释了 GPT 为什么是一个字一个字地回答。假设它已经写出“Transformer 的核心是”。下一步它会看已有上下文，给词表里所有候选 Token 打分，也许“注意力”的概率最高，于是选出它。然后把“注意力”接回输入，再预测下一个 Token。这个过程不断重复，直到生成结束符或达到长度限制。训练可以并行处理整段文本；但生成必须一步一步来，因为下一个 Token 还没出现。这也是聊天时回答会随着长度变慢的原因之一。

模型又是怎样学会这些权重的？训练目标可以非常朴素：遮住一句话后面的 Token，让模型预测下一个。给它“今天天气很”，正确答案也许是“好”；它猜错了，系统就计算误差，稍微调整所有参数。海量文本上重复这个过程，模型慢慢学到常见词序、知识之间的联系、代码模式，甚至一些可复用的推理套路。它不是把每句话背进一个抽屉，而是在大量例子中，把哪些线索通常重要，压缩进参数里。

实际使用还有一个很工程化的技巧，叫 KV Cache。生成到第五十个 Token 时，模型没有必要每次都重新计算前面四十九个 Token 的 Key 和 Value。它把已经算过的 Key 和 Value 存起来，只为新 Token 计算新增部分。这样速度会快很多，但缓存会占显存，所以长上下文更昂贵。Transformer 能成为大模型底座，除了注意力本身，还因为它适合并行训练，能随着数据、参数和计算资源一起扩展。

最后要保持一个清醒的认识。注意力权重高，不等于模型在像人一样“理解”或“相信”某句话；它只是当前计算中一个有用的关联强度。模型也会犯错、编造内容，或者把训练里见过的偏见带进回答。理解 Transformer 不等于把它神化。它真正厉害的地方，是用一套可重复堆叠的结构，把文字变成向量，让 Token 彼此交换信息，再不断预测下一个 Token。

现在把全流程在脑中走一遍：文字先切成 Token，Token 变成带位置的向量；每一层里，注意力决定该参考谁，前馈网络消化收到的信息；多层堆叠后，模型得到越来越适合当前任务的表示；生成时，它基于已有上下文选出下一个 Token。以后再看到 Query、Key、Value、Softmax 或 KV Cache，不必先记公式。先问自己：它在解决“谁该看谁、看多少、怎样更快地继续往下写”中的哪一个问题。你就已经抓住了 Transformer 的骨架。
