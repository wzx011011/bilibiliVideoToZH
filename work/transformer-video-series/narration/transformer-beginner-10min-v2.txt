先看两句话。第一句是：“奖杯放不进箱子，因为它太大。”这里的“它”，通常指奖杯。第二句是：“奖杯放不进箱子，因为它太小。”这一次，“它”通常指箱子。只改了最后一个词，指代就变了。人会自动利用上下文完成判断，计算机却只收到一串符号。Transformer 的任务，就是把这些符号变成数字，再让每个位置从上下文中取得有用的信息。接下来的十分钟，我们沿着这两句话走一遍。你会看到文字怎样进入模型，注意力怎样计算，GPT 又怎样训练和生成。

模型收到文字后，先做 Tokenization，也就是切成 Token。Token 不一定等于一个汉字，也不一定等于一个完整单词。它可能是字、词片段、数字或标点。每个 Token 会被换成一个整数编号。编号只是索引，本身没有含义。模型用这个编号查询嵌入表，取出一串可训练的数字，这就是 Token Embedding。你可以把它想成 Token 的初始坐标。初始坐标还不知道当前句子的含义，所以“它”在两句话里取出的向量相同。模型还会加入位置信息，让“奖杯放进箱子”和“箱子放进奖杯”不再被当成同一组词。到这里，文字已经变成带位置的向量序列，可以交给神经网络计算。

在 Transformer 出现以前，RNN 常按顺序处理句子。第一个位置把记忆交给第二个，第二个再交给第三个。距离一长，信息要经过很多站；训练也难以把所有位置同时算完。Self-Attention 改变了信息路线。一个位置可以直接和其他位置比较，不必沿着链条逐站传递。这里要补一个重要限定。编码器里的双向注意力，可以查看左右两边的完整输入。GPT 使用的是带因果遮罩的注意力，每个位置只能查看自己和左侧已经出现的 Token，不能偷看未来答案。所以“每个词看全句”只是帮助入门的直觉，不适用于所有 Transformer。更准确的说法是：每个位置都能直接查看规则允许它查看的上下文。

注意力怎样知道该看谁？每个输入向量会同时经过三次不同的线性变换，得到 Query、Key 和 Value。它们不是先后流过的三道工序，而是同一份输入产生的三种表示。Query 表示当前位置正在寻找什么。Key 表示每个位置提供什么匹配线索。Value 表示匹配成功后真正取回什么信息。处理“它”时，模型拿“它”的 Query，分别和“奖杯”“箱子”“太大”等位置的 Key 做点积。点积越大，表示这组线索越匹配。实际计算还会除以 Key 维度的平方根，避免数值过大。接下来，匹配分数会交给 Softmax，而 Value 暂时在旁边等待。

我们用三个玩具分数走一次完整计算。假设“它”的 Query 和三个 Key 比较后，得到二点零、一点零和零点五。Softmax 先对分数做指数变换，再除以总和。最后大约得到百分之六十三、百分之二十三和百分之十四，三项加起来正好是百分之百。模型再用这三个比例，分别乘上三个位置的 Value，并把结果相加。得到的新向量，就是“它”融合上下文后的表示。换成“因为它太小”，前面各层形成的向量会改变，匹配分数也可能改变，于是“箱子”获得更高权重。这里的数字只是演示。真实权重由数据学习，而且会随层、注意力头和上下文变化。

一个注意力头只在自己的表示空间里做一次比较。Transformer 会并行计算多个头，让模型有机会保留不同类型的关系。有的头可能对近距离搭配敏感，有的可能对指代或句法结构敏感，但这些职责不是工程师提前写死的，也不保证每个头都能被人清楚命名。各个头的结果会拼接起来，再经过一次输出投影。随后，残差连接把原输入加回来，归一化帮助数值保持稳定。接着是前馈网络。它对每个位置分别做非线性变换，进一步加工刚收到的信息。注意力负责位置之间交流，前馈网络负责位置内部处理。把这套结构重复很多层，简单的词形线索就能逐步组合成更抽象的上下文表示。

Transformer 并不只有一种外形。原始论文采用编码器加解码器，适合机器翻译。编码器先双向读取源句，解码器一边查看编码结果，一边按顺序生成目标句。BERT 一类模型主要使用编码器，擅长理解、分类和抽取。GPT 一类模型主要使用解码器，并用因果遮罩预测下一个 Token。三种结构共享注意力、前馈网络、残差连接和归一化，但信息可见范围不同。画注意力连线时，必须同时说明遮罩规则。否则一张“所有位置互相连接”的图，可能适合编码器，却会错误描述 GPT。理解这个区别，也就理解了为什么 GPT 训练时不能利用未来词来作弊。

GPT 的预训练目标很朴素：根据左侧内容，预测真实出现的下一个 Token。以“今天天气很热”为例，输入和目标会错开一位。“今天”之后预测“天气”，“天气”之后预测“很”，“很”之后预测“热”。训练数据里的实际 Token 就是监督信号，并不是语言中唯一合理的答案。如果模型在“很”后面给“冷”较高概率，而数据中的目标是“热”，交叉熵损失就会增大。反向传播计算每个参数应当怎样微调，优化器再更新参数。虽然生成必须逐个 Token 进行，训练却能借助因果遮罩，同时计算一段文本中许多位置的预测。海量样本反复执行后，模型把语言规律和大量关联压缩进参数。

真正生成时，提示词先经过多层 Transformer，最后得到词表中每个候选 Token 的分数，也叫 Logits。Softmax 把它们变成概率分布。系统可以总选最高概率，也可以结合温度、Top-k 或 Top-p 进行采样，所以同一个问题可能得到不同回答。选出的 Token 被追加到上下文，再预测下一枚 Token。注意，Token 不等于汉字，一步可能生成一个字、词片段或标点。为了避免每一步都重算全部历史，推理系统会保存旧 Token 的 Key 和 Value，这就是 KV Cache。新一步只计算新增 Token 的 K 和 V，再读取缓存。它能明显加速生成，但上下文越长，缓存占用的显存也越多。

现在把整条路线连起来。文字先切成 Token，Token 编号查询嵌入，再加入位置信息。每一层同时生成 Q、K、V，用 Query 和 Key 算匹配分数，用 Softmax 得到总和为一的权重，再对 Value 加权求和。多头结果合并后，经过残差、归一化和前馈网络。训练时，模型依据真实的下一个 Token 计算损失并更新参数。生成时，它根据已有上下文反复选择下一枚 Token，并用 KV Cache 复用历史计算。Transformer 很强，但注意力权重不等于人类式的理解，也不能保证事实正确。它仍可能编造、继承偏见或受提示方式影响。抓住“表示、匹配、汇总、预测”这四步，你就抓住了 Transformer 的核心骨架。
