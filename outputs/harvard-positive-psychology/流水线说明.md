## 二、核心流水线（6 阶段）

入口：`dub_pipeline.py`，所有阶段用 `state.json` 的内容哈希做**幂等断点**——
输入没变就跳过，输入变了自动重算对应阶段及下游。

```
segment → transcript → translation → synthesis → audio → mux → delivery
 切片     英文转写       中文字幕        TTS合成     对齐混音   封装    交付包
```

### 阶段 1：segment（切片）

- **作用**：从源 mp4 截取要处理的片段（`--full` 处理整集，或 `--duration N` 处理前 N 秒）。
- **工具**：ffmpeg `-c copy`（无重编码，快）。
- **产物**：`{stem}.source.mp4`
- **指纹**：`源文件指纹 + 时长`。

### 阶段 2：transcript（英文转写）

- **作用**：英文语音 → 英文字幕（含时间戳）。
- **模型**：faster-whisper `large-v3-turbo`（CPU / int8），`language="en"`，`word_timestamps=True`，VAD 滤波。
- **后处理**：`group_cues()` 把间隔 ≤0.35s、合并后 ≤12s 的小段拼成完整句。
- **产物**：`{stem}.en.json` + `{stem}.en.srt`
- **第1集实例**：601 条英文 cue。

### 阶段 3：translation（中文字幕）★ 关键，两条路

这一步决定中文台本质量，有两条路径：

#### 路径 A：OCR（默认、正式流程，`--subtitle-source ocr`）

本课程原片**自带中文硬字幕**，直接从画面 OCR 提取，质量远优于机翻。

1. **锚点定位**：用阶段 2 的 Whisper 英文 cue 时间戳作为字幕事件边界（取 cue 中点落在字幕稳定期），而非全局盲扫白像素。
2. **截图**：`_grab_subtitle_for_ocr()` 用 ffmpeg 在每个锚点时刻截字幕带。
3. **OCR**：调 Ollama 视觉模型 `qwen3-vl:4b` 识别截图中的中文（跳过思维链直接输出）。
4. **清洗**：`clean_ocr_cues()` 去除滚动字幕重叠、OCR 伪影（"（无中"/"内卡CC"等）。
5. **人工复核**（强制门）：`apply_review_overrides()` 应用 `review-overrides/{stem}.review.json` 里的文本/时间轴修正。
   - **注意**：代码强制 `stage=="all" 且 subtitle_source=="ocr" 时必须提供 --review-file`，否则报错。OCR 结果不能直接交付。
- **产物**：`{stem}.zh-CN.json` + `{stem}.zh-CN.srt`
- **第1集实例**：OCR 原始 590 cue → 复核后 572 cue。

#### 路径 B：NLLB 机翻（旧路径，`--subtitle-source nllb`）

- 模型 `facebook/nllb-200-distilled-600M`，`eng_Latn → zho_Hans`，批量 8 条。
- 质量较差，已被 OCR 路径取代，保留仅供对比。

### 阶段 4：synthesis（TTS 合成）

- **引擎**：GPT-SoVITS（声音克隆，本地 HTTP 服务 `127.0.0.1:9880`）。
- **参考音**：`voice-refs/cn-pro-ref.wav`（中文男声，专为课程录制）。
- **原理**：zero-shot 克隆——喂参考音频 + 其转写文本，模型学习音色与语调。
- **合成参数**（★ 2026-07-28 调参定稿）：

| 参数 | 值 | 说明 |
|---|---|---|
| `speed_factor` | 0.92 | 略放慢，更从容（P2 定稿） |
| `temperature` | 1.0 | 保持自然起伏（低于 0.9 发音含糊） |
| `top_k` | 15 | 采样候选范围 |
| `repetition_penalty` | 1.35 | 抑制重复卡壳 |
| `seed` | 42 | 固定可复现 |

- **产物**：`clips/{指纹}/{0001..NNNN}.mp3`（每条 cue 一个 mp3）。
- **指纹含合成参数**：改 speed/temp 会让旧 clip 失效自动重合成。

### 阶段 5：audio（对齐混音）

- **作用**：把所有 clip 拼成与视频等长的整条中文音轨，并控制语速保持口型同步。
- **算法**：`schedule_audio()` 按每个 cue 的时间窗 + clip 实际时长，计算 `tempo`（加速倍率）：
  - 优先用 `speech_tempo=0.98`（略慢于合成音）；
  - 若 clip 太长塞不下窗口，自动加速，但上限 `max_tempo=1.05`（防止过快听不清）；
  - clip 之间用静音填充，前一个没播完下一个就紧接。
- **工具**：ffmpeg `atempo` 调速 + pydub 拼接，输出 48kHz 单声道 wav。
- **产物**：`{stem}.zh-CN.wav`
- **第1集实例**：`speech_tempo=0.98, max_tempo=1.05`。

### 阶段 6：mux（封装）

- **作用**：合成最终双音轨 + 双字幕 mp4。
- **布局**：
  - 视频流：原视频（av1，copy 不重编码）
  - 音频流 0：**中文配音**（aac 160k，默认轨）
  - 音频流 1：**英文原声**（copy，次轨）
  - 字幕流 0：**中文字幕**（mov_text，默认）
  - 字幕流 1：**英文字幕**（mov_text）
- **产物**：`{stem}.dual-audio.bilingual-subtitles.mp4`

### 阶段 7：delivery（交付包，可选 `--delivery-dir`）

- **作用**：原子化生成自包含、带校验和的交付目录。
- **结构**：
  ```
  {stem}-delivery/
  ├── video/      {stem}.dual-audio.bilingual-subtitles.mp4
  ├── audio/      {stem}.zh-CN.dub.m4a（中配 AAC）
  │               {stem}.en.original.m4a（英文原声）
  ├── subtitles/  {stem}.zh-CN.srt / {stem}.en.srt
  └── metadata/   manifest.json（含 revision 记录）
                  workflow.json（引擎/参数/参考音）
                  ffprobe.json
                  {stem}.reviewed-cues.json（复核后 cue）
                  {stem}.review-overrides.json（复核修正记录）
                  SHA256SUMS.txt（全部文件校验和）
  ```
- **原子性**：先写 staging 目录，全部成功后 `replace` 成正式目录；任一步失败回滚删除。

## 四、运行命令（以第 N 集为例）

### 4.1 仅生成可复核字幕（先跑这步，人工复核）

```bash
cd D:\work\wzx\work\headless-dub
.venv-ocr\Scripts\activate

python dub_pipeline.py \
  --input "D:\work\wzx\outputs\harvard-positive-psychology\02 - ...第2讲.mp4" \
  --full \
  --output "D:\work\wzx\outputs\harvard-positive-psychology\episode-02-work" \
  --subtitle-source ocr \
  --ocr-model qwen3-vl:4b \
  --artifact-stem episode-02 \
  --stage subtitles
```

产出 `episode-02.zh-CN.srt` → 人工逐条核对 → 写成 `review-overrides/episode-02.review.json`。

### 4.2 全流程出交付包（复核后）

```bash
python dub_pipeline.py \
  --input "...第2讲.mp4" \
  --full \
  --output "...episode-02-work" \
  --subtitle-source ocr \
  --ocr-model qwen3-vl:4b \
  --artifact-stem episode-02 \
  --review-file review-overrides/episode-02.review.json \
  --delivery-dir "...episode-02-delivery"
```

合成参数用默认（speed=0.92, temp=1.0），无需显式传。

### 4.3 复核文件格式（schema_version 1）

```json
{
  "schema_version": 1,
  "overrides": [
    {"start": 489.58, "text": "修正后的整句中文"}
  ],
  "previous_ends": [
    {"start": 489.58, "end": 495.20}
  ],
  "restored_cues": [
    {"start": 100.0, "end": 105.0, "text": "OCR 漏掉需补回的句"}
  ]
}
```

- `overrides`：按 cue 的 `start` 时间戳定位，替换文本。
- `previous_ends`：修正 cue 结束时间（时间轴漂移）。
- `restored_cues`：补回 OCR 漏识别的整句。
- **每个 start 必须命中源 cue**，否则报错（防止 review 文件错配到别的视频版本）。

## 五、关键约束与坑

1. **OCR 交付必须经人工复核**——代码强制 `--review-file`，否则 `stage=all` 报错。
2. **GPT-SoVITS 没有语气旋钮**——音色/语调由参考音频决定，speed/temp 只能微调节奏与稳定性。
3. **改合成参数会触发重合成**——fingerprint 含 speed/temp，旧 clip 自动失效。
4. **第1集（speed=1.0）与第2集起（speed=0.92）有细微语速差**——可接受，未重跑第1集。
5. **豆包工具（doubao-tts-tool）未接入主流水线**——它是 chat_tts 复读模式，只能朗读豆包已生成回复，无法按台本逐句合成，故未用作主线音色。
