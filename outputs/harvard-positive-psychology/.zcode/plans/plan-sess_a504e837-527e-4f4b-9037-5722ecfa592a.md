# 全面替换 OCR 引擎：qwen3-vl → RapidOCR

## 目标
把字幕 OCR 引擎从笨重的视觉大模型 qwen3-vl:4b（经 ollama，~21s/条，纯CPU）换成轻量文字识别 RapidOCR（~1.8s/条，纯CPU）。实测快 11 倍、中文准确率持平。

## 改动范围（2 个代码文件 + 1 个依赖 + 重跑数据）

### 1. `subtitle_ocr.py` — 核心替换（阶段B 的 `ocr_events`）

**保留不动**（关键）：`_detect_stage`（阶段A 字幕边界检测）、`_sample_timestamps`（多帧采样）、`_merge_fragment_texts`（片段合并）、`on_result`（断点持久化）、`run()` 编排逻辑。

**替换 `ocr_events()` 内部的单帧识别**（第 419-445 行）：
- 删除 `from openai import OpenAI` + `client = OpenAI(base_url=..., api_key="ollama")` + chat.completions.create 调用
- 改为：模块级懒加载 `from rapidocr_onnxruntime import RapidOCR`（单例引擎，复用），对截图调用 `engine(img)`，拿到 `[(box, text, score), ...]`
- **中文行过滤**（已验证 100% 有效）：用 `re.search(r'[\u4e00-\u9fff]', text)` 保留含中文字符的行，丢弃英文行
- 删除 qwen3-vl 专用的 prompt 字符串（第 424-426 行的 `/no_think` 前缀那段）
- 删除 `_image_to_data_url`（base64 仅给 OpenAI 用，RapidOCR 直接吃文件路径/数组）和 `_clean_ocr_output`（视觉模型的 think 标签清洗，RapidOCR 不需要）

**清理参数传播链**：
- `ocr_events` / `run` 的 `base_url` 参数 → 删除（RapidOCR 无 HTTP 端点）
- `model` 参数语义变化：从"ollama 模型名"变成"OCR 引擎标识"，默认值 `qwen3-vl:4b` → `rapidocr`
- CLI `--base-url`（第 629-630 行）→ 删除；`--model` 默认 → `rapidocr`，help 文案更新

### 2. `dub_pipeline.py` — 默认值与元数据

- `run_pilot` 的 `ocr_model` 默认值 `qwen3-vl:4b` → `rapidocr`（第 954 行）
- CLI `--ocr-model` 默认值 `qwen3-vl:4b` → `rapidocr`，help 文案更新（第 1190-1194 行）
- 调用 `subtitle_ocr.run()` 处不变（第 1031-1033 行，本来就只传 `model=`，不传 base_url）
- **fingerprint 影响**：第 1020 行的 translation 指纹含 `ocr_model`，默认值变了会让旧字幕缓存自动失效重跑（正是我们要的）

### 3. `requirements.txt` — 依赖增删

- 删除 `openai>=2.6,<3`（OCR 不再用；确认 dub_pipeline 别处不用才能删——需核查 NLLB 路径，若不用则删）
- 新增 `rapidocr-onnxruntime`

### 4. 数据重跑（第2集）

- 清空 `episode-02.source.events.json` 中已识别的 214 条文本（保留 start/end 边界，把 text 置空）
- 重跑命令：`python dub_pipeline.py --input ... --stage subtitles --subtitle-source ocr --artifact-stem episode-02`
- 预计 640 条 ~20 分钟（含 ffmpeg 截图开销）

- `_detect_stage` 阶段A、Whisper 转写、NLLB 路径 — 不动
- 第1集已交付内容 — 不动（它已用 qwen3-vl 完成，不重跑）
